# Muse-chat-relay

進行中の作業を、自己完結した引き継ぎ文つきで専用のサイドチャットへ引き継ぐための [Muse](https://muse.ai) 用スキルです。

[English README](README.md)

## なぜ必要か

Muse のサイドチャットは、会話履歴ゼロで始まります。ユーザーの好み・常駐ファイル・メモリといった常識は読み込まれますが、作業の途中経過（途中で決めたこと、完了／未着手の状態、次の一手）は自動では引き継がれません。

このスキルは、その引き継ぎ手順を定型化したものです：

1. 引き継ぐ作業を1単位に区切り、正本を特定する
2. 会話の要約ではなく、一次資料で現在の状態を確認する
3. 引き継ぎ文を固定の9節構成で書く：目的／背景と経緯／確定した決定事項／現在の状態／成果物と正本への参照／未決事項／次の一手／制約と注意点／引き継ぎ元
4. fresh なサイドチャットを立てて送り、**送信後に受け側を読み戻して全文の到達を確認する**（初回の実使用で実際に文が途中で切れたため、この確認を手順に入れています）
5. 正本に移行を記録し、元のチャットではその作業を止める

もう1つの形態として **追加 relay** も定義しています。担当サイドチャットが既にある場合は、新規作成はせず、新しい依頼や診断結果だけを差分で渡します。移行ではないので、元のチャットの作業は止めず、承認範囲を広げもしません。

## 前提

- サイドチャットが使える Muse 環境
- このスキルは Muse のチャット用道具（`chat.create` / `chat.send_message` / `chat.read_messages` / `chat.list`）を使います。他のエージェント環境では、手順の考え方は使えますが、チャットの作成・送信の部分はその環境の仕組みに読み替える必要があります

## 導入

### 推奨：Muse に頼む

自分の Muse に、こう頼むだけです：

> https://github.com/inuro/muse-chat-relay の relay スキルを導入して

Muse がこのリポジトリを読み、`SKILL.md` と `skill.yaml` をカスタムスキル置き場の `relay` フォルダ（`~/workspace/custom-skills/relay/`）へ入れてくれます。Muse ではこれが自然な導入方法で、ターミナルは不要です。

### 決定論的に導入したい場合

自分で確定的に入れたい場合は、リポジトリをカスタムスキル置き場へ直接 clone します：

```sh
git clone https://github.com/inuro/muse-chat-relay.git ~/workspace/custom-skills/relay
```

（`examples/` フォルダは説明用です。導入しなくても動きますが、一緒に入れておいても問題ありません）

## 使い方

作業を移したいときに、Muse へ自然な言葉で頼みます：

- 「この作業をサイドチャットへ relay して」
- 「/relay 調査の件」
- 「既存の○○チャットへ、この修正を追加 relay して」（追加 relay）

Muse が引き継ぎ文を組み、サイドチャットを作成して送信・到達確認を行い、移行を正本に記録します。

## ファイル

- `SKILL.md` — 手順の本体（スキル本体。英語）
- `skill.yaml` — Muse 用のスキルメタデータ
- `examples/handover-example.md` — 引き継ぎ文の実例（架空のサンプル）

## 注意

- 引き継ぎ文に秘密情報（パスワード、認証コード、API キー等）を入れないでください。スキルにも明記していますが、送信前に人間が確認する際の観点としても重要です
- これは有志による非公式のスキルです。Meta の製品ではなく、Meta と提携したものでもありません
